= 🇫🇷 Support de cours pour le module devops, sous section docker

Cours disponible à cette adresse : https://gounthar.github.io/cours-devops-docker/main[]

🇺🇸

This repository hosts the source of the slide decks.

Slides are written in https://asciidoctor.org/[Asciidoctor language] and rendered as HTML and PDF using https://revealjs.com/[reveal.js].

== How-to Work with this Presentation?

=== Requirements

* You need:
** Docker CE 20.10+ (with local bind-mount capability -
Docker Desktop or a local Linux Docker CE install)
** https://www.gnu.org/software/make/[GNU Make] in your `PATH`

== Generate the slides

* If you want to generate the slide-deck in "one shot":
** Clone the repository
** Run the following `make` command:

[source,bash]
----
make build
----

** Open the resulting file `./dist/index.html`

=== Working on the slides with Live-reloading

* If you want to build and serve the slides locally,
with a live-reloading capability
(e.g. change a `*.adoc`, regenerate the HTML and reload the web-browser)
to get a WYSIWYG experience:

** Clone the repository
** Run the following `make` command:
+
[source,bash]
----
make serve
----

** Open the URL link:http://localhost:8000
** Edit one of the `*.adoc` file, save it, and see the page reload
*** it is valid for images and styles also

=== Generated media

Two files under `content/media/` are produced by the build rather than
committed, so do not edit them by hand:

* `qrcode.png` -- the QR code pointing at this deck's published URL;
* `anatomie-1.svg` … `anatomie-8.svg` -- the eight steps of the `🩻 Anatomie`
  slide, drawn by `scripts/gen_anatomy_card.py` and regenerated by every
  `make build`.

The Anatomie card carries a timestamp, because the slide exists to show that a
container runs a command and returns *the result of the moment* -- and the PNG
it replaces still showed September 2023. A timestamped file cannot be committed
and checked the way `content/media/dockerfile-defi-*.svg` are: it would be stale
the instant it was committed. So these are in `.gitignore`, and `check-assets`
covers them instead, since it runs after the build.

The two commands the card draws live in `PANELS`, at the top of the generator,
and nowhere else. A weekly job runs them for real and opens an issue when one
stops working -- which is what `centos` did, unnoticed, inside a PNG (see issue
#547):

[source,bash]
----
python3 scripts/gen_anatomy_card.py unused --print-commands
python3 scripts/gen_anatomy_card.py content/media/anatomie --steps \
  --at 2023-09-25T19:33:19          # frozen timestamp, for comparing renders
----

=== Run checks on the generated HTML

`make verify` runs the checks that are deterministic and offline, so they can
gate a pull request without ever failing for a reason outside this repository:

* `check-dashes` -- no en/em dash inside a shell command, where it looks like a
  hyphen on a slide and breaks the command when copied;
* `check-diagrams` -- the committed SVG of a diagram that shows a Dockerfile
  still matches that Dockerfile;
* `check-prune` -- the twelve cases of `scripts/test_prune_gh_pages_previews.sh`,
  which guard the weekly `gh-pages` pruning described under CI/CD below;
* `check-opacity` -- the slide background opacity declared in the source is the
  one the generated HTML carries;
* `check-assets` -- every local file the generated HTML points at exists.

It needs the deck to have been generated first, since two of the five checks
read the built HTML:

[source,bash]
----
make build
make verify
----

Or run the `all` command, as the CI process does:

[source,bash]
----
make all
----

==== Checking external links

External links are checked by a separate target, on demand:

[source,bash]
----
make build
SOURCE_FILE=index-examen.adoc make build
make pdf
make check-links
----

It is kept out of `make verify` on purpose. Link rot depends on other people's
uptime, so a pull request would fail for reasons its author cannot fix; a gate
that cries wolf gets ignored, then switched off. A scheduled job runs it every
Monday instead and opens or updates an issue with the findings.

Exclusions and the browser user agent live in `lychee.toml`, each with the
measurement that justifies it -- campus hosts a runner cannot resolve, the
`localhost` addresses the course teaches, and pages behind authentication.

Re-running the check several times in an hour trips GitHub's anonymous limit of
60 requests, and the run then reports live `github.com` URLs as broken. Export a
token to lift it; it is forwarded to the checker only when you set it, and the
scheduled job does not:

[source,bash]
----
GITHUB_TOKEN="$(gh auth token)" make check-links
----

NOTE: The W3C compliance validation this section used to promise has never
existed. See issue #486 for the history, and the follow-up issue linked there
if it is wanted.

=== Dependencies management

As NPM is used for expressing the dependencies, you can execute the following chores:

* Lock the dependencies (e.g. generating the file `package-lock.json` from the file `package.json` and the content of `nodes_modules`):

[source,bash]
----
make dependencies-lock-update
----

* Upgrade all dependencies (e.g. update the file `package.json`)

[source,bash]
----
make dependencies-update
----

=== Maintenance tasks inside the container

If you want to get a shell inside the "build and serve" container,
run the following `make` command:

[source,bash]
----
make shell
----

==== Example: Updating the package.json (and package-lock.json) Dependencies

[source,bash]
----
$ make shell
# Update the `package.json` file to latest versions
/app > ncu -u
# Update the `package-lock.json` file from `package.json`
/app > npm install
----

== CI/CD

- GitHub Actions are used to continuously build, validate and deploy the changes on this slides.
- GitHub Page is used to serve the generated HTML and PDF content (deployment target).

=== Published previews, and when they disappear

Every pushed branch gets its own preview at
`https://gounthar.github.io/cours-devops-docker/<branch>/`. The course itself is
the `main` one, linked at the top of this file.

A preview weighs about 155 MB, and nothing used to remove it when its branch was
deleted. By September 2026 the published branch held 68 previews of branches
that no longer existed, 10.86 GB in total, of which `main` was 1.4 % -- and the
Pages build started failing outright, so the site stopped updating while
`gh-pages` held perfectly good content. See issue #542.

A scheduled job now removes, every Monday, the previews whose branch is gone:

[source,bash]
----
# what it would delete, without deleting anything
PRUNE="$PWD/scripts/prune_gh_pages_previews.sh"
git fetch origin gh-pages
git worktree add /tmp/ghp gh-pages
(cd /tmp/ghp && "$PRUNE" --dry-run)
git worktree remove /tmp/ghp
----

`main` is spared unconditionally. So the preview URL of a merged branch stops
answering within a week of the branch being deleted: send people the `main` URL,
never a branch one.

The job deletes files on a published branch, once a week, with nobody watching,
so its twelve cases run offline as part of `make verify`. Two of them are
regressions: a branch prefix that flips over time (`feature` deleted, then
`feature/docs` created, leaving both previews published) and a tag named `main`
satisfying the guard that was meant to check the branch. Both deleted the
preview of a live branch.

[source,bash]
----
./scripts/test_prune_gh_pages_previews.sh      # case by case
----
