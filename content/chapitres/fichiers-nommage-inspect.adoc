== 🎓 Travaux pratiques #6

Étapes:
[%step]
* Lancer un container `nginx`
[%step]
* Trouver la syntaxe permettant d'extraire le "CMD" qui a été passé au démarrage du container
[%step]
* Trouver une seconde méthode pour faire la même chose

[.notes]
--
On démarre un container nginx avec la commande
[source,bash]
----
docker container run --detach --name my-web nginx
----

Une solution facile est de faire:

[source,bash]
----
docker container inspect --format '{{json .Config.Cmd }}' my-web | jq .
----

Ça nous donne:
[source,json]
----
[
  "nginx",
  "-g",
  "daemon off;"
]
----

Qu'on pourrait nettoyer pour avoir `nginx -g daemon off;` avec:
[source,bash]
----
# jq -r : une ligne par élément ; tr : tout sur une ligne
docker container inspect --format '{{json .Config.Cmd }}' my-web \
  | jq -r '.[]' | tr '\n' ' '
----
qui donne `nginx -g daemon off;`.

Une autre solution serait:
[source,bash]
----
# awk : découpe la colonne COMMAND, entre les en-têtes
# COMMAND et CREATED
docker container ls --filter "name=my-web" --no-trunc \
  | awk 'NR==1 {cmd=index($0, "COMMAND"); created=index($0, "CREATED")}
         NR>1  {print substr($0, cmd, created-cmd)}'
----

qui donnerait `"/docker-entrypoint.sh nginx -g 'daemon off;'"`.
--

==  ✅ Solution Travaux Pratiques #6
[source,bash]
----
# awk : découpe la colonne COMMAND, entre les en-têtes
# COMMAND et CREATED
docker container ls --filter "name=my-web" --no-trunc \
  | awk 'NR==1 {cmd=index($0, "COMMAND"); created=index($0, "CREATED")}
         NR>1  {print substr($0, cmd, created-cmd)}'
----

[%step]
qui donnerait `"/docker-entrypoint.sh nginx -g 'daemon off;'"`.

[%step]
Pourquoi deux réponses ? `docker container ls` affiche `ENTRYPOINT` + `CMD`, `.Config.Cmd` le seul `CMD`.

[.notes]
--
Sorties rejouées le 2026-10-03 avec `nginx:1.31.6-alpine3.24` (Docker 29.8.0).
L'image nginx déclare `ENTRYPOINT ["/docker-entrypoint.sh"]` et `CMD ["nginx", "-g", "daemon off;"]` :
`docker container inspect --format '{{json .Config.Entrypoint}}' my-web` donne `["/docker-entrypoint.sh"]`.

La colonne `COMMAND` de `docker container ls` met les deux bout à bout ; `.Config.Cmd` ne contient que le `CMD`.
Un argument passé à `docker container run` remplace le `CMD` et s'ajoute à l'`ENTRYPOINT` (diapositives « ENTRYPOINT + CMD » du chapitre images).
La forme shell ajoute d'office `/bin/sh -c` ; en forme exec, il n'y a un shell que si on l'écrit soi-même (`["sh", "-c", "..."]`).
--

== 🔍 Que nous dit docker container inspect ?

L'ancienne forme, encore dans beaucoup de tutoriels, échoue avec Docker 29 :

[source,bash]
----
docker container inspect --format "{{.NetworkSettings.IPAddress}}" <ContainerID>
template parsing error: [...] map has no entry for key "IPAddress"
----

L'adresse n'est plus que sous `.NetworkSettings.Networks.<réseau>`, d'où le `range`.

== ✅ Solution travaux pratiques #7

Derrière le proxy de l'université, `mvn package` échoue : Maven ignore `HTTP_PROXY` et `HTTPS_PROXY`.
Il lit son proxy dans `~/.m2/settings.xml`.

[source,xml]
----
include::../code-samples/fichiers/reseau/settings.xml[]
----

[source,bash]
----
mkdir -p ~/.m2 && cp settings.xml ~/.m2/settings.xml
----

Dans un `Dockerfile`, on le monte comme secret de build, le temps du seul `RUN mvn package` : il ne reste pas dans l'image.
Sans `--secret` (hors de l'université), le montage est simplement absent.

== 🧩 Une première solution

Avec un autre exemple

[source,bash]
----
#!/bin/sh
echo Building alexellis2/href-counter:build

docker image build --build-arg https_proxy=$https_proxy --build-arg http_proxy=$http_proxy \
    -t alexellis2/href-counter:build . -f Dockerfile.build
docker container create --name extract alexellis2/href-counter:build
docker container cp extract:/go/src/github.com/alexellis/href-counter/app ./app
docker container rm -f extract

echo Building alexellis2/href-counter:latest
docker image build --no-cache -t alexellis2/href-counter:latest .
rm ./app
----
