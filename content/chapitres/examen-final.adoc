== Architecture : Vue d'ensemble

* Architecture **production-ready** conteneurisée
* Support application Java EE
* Stack complète : Reverse Proxy + App Server + Database + ELK
* Démarrage : `docker compose up -d`

[{invert}]
== Exigences fonctionnelles

[.title]
**Partie obligatoire**

[{invert}]
== 1. Architecture multi-tiers

* **Reverse-proxy** : load-balancing si plusieurs instances
* **Serveur d'app** : WAR Java EE correctement configuré
* **Base de données** : PostgreSQL ou MySQL, données persistantes
* **Stack ELK** : Elasticsearch + Logstash + Kibana

[{invert}]
== 2. Docker Compose

* Fichier `compose.yml` bien structuré
* Variables dans `.env` (`.env.example` committé)
* Networks : isolation des services
* Volumes **nommés** pour la persistance

[{invert}]
== 3. Images Docker

* **Multi-stage builds** quand pertinent
* Taille : < 500 MB (app), < 200 MB (services)
* `.dockerignore` bien configuré
* **Pas de secrets** dans les images

[{invert}]
== 4. Health checks

* Health checks sur **tous** les services
* Restart policies : `on-failure` ou `unless-stopped`
* `depends_on` avec `condition: service_healthy`
* Temps de démarrage total < 2 minutes

[{invert}]
== 5. Resources & Logging

* **Limites CPU/mémoire** sur chaque service
* Logs au format **JSON** quand possible
* Intégration **Logstash** → **Kibana**
* Dashboards de base exploitables

[{invert}]
== 6. Sécurité

* Conteneurs avec `USER` **non-root**
* Secrets : Docker secrets ou env vars (jamais en clair)
* **Trivy** : scanning de vulnérabilités

[{invert}]
== 7. Documentation

**README.md complet :**

* Architecture (schéma + explications)
* Prérequis, installation, configuration
* Utilisation et troubleshooting
* **Justifications** des choix techniques
