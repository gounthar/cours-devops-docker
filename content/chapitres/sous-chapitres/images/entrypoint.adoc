== CMD vs ENTRYPOINT

Cas d'usage : énoncé du besoin.

[%step]
Besoin : je veux utiliser `cURL` mais il n'est pas présent sur la machine hôte.

[%step]
**Facile !**

[%step]
[source,bash]
----
docker container run --rm curlimages/curl curl -x http://cache-etu.univ-artois.fr:3128 -L --connect-timeout 60  "http://google.com"
----

[%step]
image::1956754704-image11.jpeg[]

[.notes]
--
Pour ceux qui n'auraient pas de proxy parce que vous n'utilisez pas le réseau de la fac... On peut en lancer un avec Docker.
Tout d'abord, créer un fichier `squid.conf` avec comme contenu :

[source,apache]
----
include::../../../code-samples/images/cmd-vs-entrypoint/squid.conf[]
----

On peut ensuite lancer le proxy :
[source,bash]
----
docker container run --name squid -d --restart=always --publish 3128:3128 \
  -v $(pwd)/squid.conf:/etc/squid/squid.conf ubuntu/squid:6.6-24.04_beta
----

Puis changer la commande en :
[source,bash]
----
docker container run --rm --add-host=host.docker.internal:host-gateway \
  curlimages/curl curl -x http://host.docker.internal:3128 -L --connect-timeout 60 "http://google.com"
----

`host.docker.internal` n'existe d'office que sous Docker Desktop.
Sous Linux (Codespaces compris), `--add-host=host.docker.internal:host-gateway` crée ce nom et le fait pointer vers l'hôte ; sous Docker Desktop, l'option ne gêne pas.
Même option pour lancer `my-curl` avec le `CMD` ou l'`ENTRYPOINT` « votre propre proxy docker ».

== ENTRYPOINT + CMD

[.column.is-one-fifth]
--
Une URL par défaut, toujours remplaçable.

[%step]
`ENTRYPOINT` : la commande.

[%step]
`CMD` : ses arguments par défaut.
--

[.column.is-half]
--
[source,dockerfile]
----
include::../../../code-samples/images/cmd-vs-entrypoint/my-curl/defaut/Dockerfile[]
----

[.column]
--
[%step]
[source,bash]
----
docker image build -t my-curl:3.0 .
----

[%step]
[source,bash]
----
docker container run --rm \
  my-curl:3.0
  % Total    % Received [...]
100    713   0    713   [...]
<!doctype html><html [...]
[...]<title>Example Domain</title>
----

[%step]
[source,bash]
----
docker container run --rm \
  my-curl:3.0 http://neverssl.com
  % Total    % Received [...]
100   3961 100   3961   [...]
<html>
  <head>
    <title>NeverSSL [...]
----
--

[.notes]
--
Seule différence avec `my-curl:2.0` : la dernière ligne, `CMD ["http://example.com"]`.
Commande lancée = `ENTRYPOINT` suivi de `CMD`. Un argument passé à `docker container run` remplace tout le `CMD`, jamais l'`ENTRYPOINT` (pour celui-là, il faut `--entrypoint`).
Sorties rejouées le 2026-10-02 (Docker 29.8.0, alpine:3.24), raccourcies ; les tailles de page varient.
--

== Forme exec ou forme shell ?

[.column.is-half]
--
[source,dockerfile]
----
# Forme exec (JSON)
ENTRYPOINT ["curl", "-L", ...]

# Forme shell
ENTRYPOINT curl -L ...
----

[%step]
La forme shell passe par `/bin/sh -c`.

[%step]
**`CMD` et les arguments de `run` sont ignorés.**
--

[.column]
--
[%step]
[source,bash]
----
docker container run --rm \
  my-curl:shell http://neverssl.com
curl: (2) no URL specified
----

[%step]
[source,bash]
----
docker image inspect my-curl:shell \
  --format '{{json .Config.Entrypoint}}'
["/bin/sh","-c","curl -L [...]"]
----

[%step]
Règle : forme exec pour `ENTRYPOINT` et `CMD`.
--

[.notes]
--
Dockerfile complet de `my-curl:shell` :

[source,dockerfile]
----
include::../../../code-samples/images/cmd-vs-entrypoint/my-curl/shell/Dockerfile[]

Sorties rejouées le 2026-10-02 (Docker 29.8.0, alpine:3.24). Sans argument, même message : le `CMD` n'est pas transmis non plus.

On lit souvent qu'en forme shell, `sh` devient le PID 1 et ne relaie pas les signaux (`docker stop` lent).
Mesuré sur alpine:3.24, ce n'est pas le cas : le `sh` de BusyBox remplace son processus par la commande (PID 1 = `ping localhost`, même avec `echo start; ping localhost`).
`docker stop` a pris le même temps (3,4 s, code 137) en forme exec et en forme shell. Avec d'autres shells ou d'autres images : non mesuré.
